# 本地可靠性与交互优化（2026-11-02）

## 已按优先级完成

1. **忌口过滤**：主料与调味料统一建立关键词；内置、社区缓存及个人菜谱使用同一过滤函数。补充西红柿/番茄、芫荽/香菜、蒜瓣/蒜蓉/蒜等常见别名，搜索同步归一。仍保留严重过敏警示，不声称能覆盖所有过敏原或交叉接触风险。
2. **真实保存反馈**：菜谱、资料、健康记录、删除/恢复和完成标记等重要操作采用候选快照，写成功后才替换内存；写失败保留原数据和旧图片。身高与同日体重一起提交。正式菜谱与对应草稿清除在同一快照中保存，避免旧草稿重新出现。昵称、忌口、清除记录等页面均处理失败提示。
3. **编辑信息保留**：保留未修改的多标签、抽取池、食材备料说明、步骤图片路径、来源、许可、来源版本和其他教程。新增、排序步骤保留各自身份；云端临时图片地址不写入持久数据。个人改编可以继续解析来源步骤图。旧内置修改按确定的ID恢复出处；旧步骤仅在ID和正文均相同时恢复来源图片，不为已改动步骤强配图。无法追溯原始ID的旧个人副本不猜测来源。复制菜谱投稿时把署名与许可同时写入提示，兼容旧云函数字段白名单。
4. **本地草稿**：编辑变化700ms后保存；切后台或离开时补存，重新进入可确认恢复，支持放弃编辑。选择图片后持久化草稿图片，启用可用的离开提醒。最多保留最近20份，草稿仍不是正式菜谱。
5. **个人备份**：“我的 → 个人备份与图片空间”中导出/恢复JSON；含资料、健康记录、收藏、计划、个人菜谱、内置修改及个人图片，不含社区缓存和草稿。文件含未加密个人数据，导出前提醒，仅由用户通过微信文件发送能力选择保存位置，本程序不上传至CloudBase。恢复需二次确认替换；验证格式、版本、结构、ID、日期、图片编码与引用，先写新图再提交快照；失败回收新文件，成功后才清理旧图。最大12MB、512张图片；没有文件导出能力时明确要求更新微信。
6. **图片与空间**：新封面按长边最多1280px、质量72进行优化，并检查输出不超过1MB；旧基础库忽略尺寸参数时不直接保存超大图。图片空间统计、50MB提醒与手动清理无引用旧图；清理目录限定在应用自己的recipe_images中，保护现用菜谱、草稿引用及24小时内的新图。头像替换也先保存资料再清理旧图。
7. **视觉与检索**：新增蔬菜、鸡肉、肉类、汤羹、主食和辛辣6张不同的代码几何插画；9种类型不再共用番茄炒蛋。收藏底栏改为独立书签图标。6张兜底图与2个底栏PNG合计9292字节，无新增网络请求。收藏与个人菜谱可共用关键词、菜系和餐食筛选，保留分页与无结果提示。
8. **烹饪计时**：按实际时间戳累计；页面切后台不暂停、回前台补齐，主动暂停保留不足1秒余量；切后台关闭屏幕常亮，返回再恢复。关闭页面即结束，不提供后台闹钟或杀进程后续计时。

## 性能检查结论与暂缓事项

- 保留首页16张首屏卡片、分页增量setData、搜索防抖及详情分包；备份/图片优化工具仅在features内，不进入主包依赖。
- 本机Node模拟基准（单次运行，首轮预热后5次中位数）：389道约1.26ms，1000道约2.52ms，5000道约12.96ms；首屏均16张，模拟初始setData载荷约4.2KB。数据随机器、环境和代码变化，不是微信真机渲染/启动性能。
- **暂未引入虚拟列表**：现有分页控制首屏，但长时间滚动仍会累积节点；需要在低端Android和iOS上记录实际帧率、内存、滚动位置，再决定是否窗口化渲染，避免无依据的布局重构。

## 发布前仍需真机验收

- 微信文件分享与聊天文件选择能否导出到小程序外；确认取消导出/导入不修改个人数据。
- 图像尺寸/质量在iOS与Android基础库实际生效；相机、相册返回与切后台时草稿不丢。
- 备份在另一台设备恢复后个人封面、步骤图与头像能否显示；空间不足或中断不破坏旧数据。
- 小屏设备的草稿条、筛选栏、备份按钮；底栏独立图标与弱网/断网分类兜底图。
- 烹饪后台往返、主动暂停、关闭页面的提示符合实际行为。

本轮未推送GitHub、未部署云函数、未操作生产数据。这些本地优化不新增数据库或云端服务；工作区此前的recipeCommunity分类/同步改动仍按其既有发布说明部署。
